# 🍊 Fruitly — fresh-fruit e-commerce on Harakumo

A complete, production-style fruit store built with **Next.js 16 + TypeScript + Tailwind v4**, using **one Harakumo API key** for the whole backend:

| Need | Harakumo service | How it's used |
|---|---|---|
| Database | **Edge SQLite** — `POST /api/databases/:id` | Users, sessions, OTP codes, products, categories, addresses, coupons, orders, order items/events, newsletter |
| Email | **Mail** — `POST /api/mail/send` | Verification codes, sign-in codes, password reset, welcome, order confirmation, shipping updates, admin "new order" |
| Payments | **Payments (Stripe Connect)** — `POST /api/projects/:id/payments`, `POST /api/payments/:account` | Hosted card checkout (+ Cash on Delivery fallback) |
| File storage | **Storage** — presigned PUT/GET | Admin product-image uploads, served through `/api/media/*` |
| AI | **AI Gateway** — `POST /api/ai/playground` | "Tips from our AI produce expert" on product pages |
| Auth directory | **Auth pool** — `POST /api/auth-pools/:id` | Users are mirrored into the pool (directory only — see *Security notes*) |
| Config / deploy | **Env vars** + **Deployments** | `npm run harakumo:env`, `npm run harakumo:deploy` |

Everything else (password hashing, sessions, OTP logic, cart, checkout, admin) is implemented in this repo.

---

## Features

**Storefront** — home (categories, favourites, how-it-works, testimonials), category & search browsing, sorting, product pages with nutrition, **AI tips**, **ratings & reviews** (verified-purchase badge, JSON-LD), related products, **wishlist**, cart (persisted locally, re-priced server-side), coupons (`WELCOME10`, `FRESH5`), free shipping threshold, newsletter signup, sitemap/robots.

**Accounts** — sign-up → 6-digit email verification (OTP) → welcome email; password sign-in; **passwordless sign-in by emailed code**; forgot/reset password by code; profile; address book; change password (signs out other devices); active-session list with per-device revoke; rate-limiting + OTP attempt caps.

**Checkout & orders** — address selection / new address, card (Stripe hosted checkout via Harakumo Payments — offered automatically once the connected account's Stripe onboarding is complete) or cash on delivery, server-side price & stock validation with atomic stock reservation, order numbers, confirmation emails, order history & tracking timeline, **reorder**, customer cancellation (restores stock), payment confirmation on return from Stripe, webhook endpoint.

**Admin** (`/admin`, role = `admin`) — dashboard (revenue, orders, customers, low stock, **live Stripe onboarding status** with refresh), product CRUD with **image upload to Harakumo Storage**, order management (status + payment status, customer notification email with note), customer list with role management, **coupons** and **categories** management.

**Dev tooling** — `/dev/mailbox` (every email the app sent, incl. OTP codes; disabled in production), `/api/health`, local SQLite fallback when no Harakumo key is configured, short-TTL in-memory catalogue cache, CSRF origin check on all mutating API routes.

## Quick start

```bash
npm install
cp .env.example .env.local        # put your hk_live_… key in HARAKUMO_API_KEY, set ADMIN_EMAILS
npm run harakumo:setup            # creates project/DB/bucket/auth pool (+ payments), runs migrations, seeds 31 products, writes ids to .env.local
npm run dev                       # http://localhost:3000
```

Sign up with an email listed in `ADMIN_EMAILS` to get the admin role automatically (or `npm run admin:promote -- you@example.com`).

### Scripts

| Script | What it does |
|---|---|
| `npm run harakumo:setup` | Idempotent provisioning on Harakumo + migrate + seed + `.env.local` update |
| `npm run db:migrate` / `db:seed` | Apply schema / (re)seed catalogue against the configured DB |
| `npm run db:query -- "SELECT …"` | Run SQL against the configured DB (Harakumo or local) |
| `npm run admin:promote -- email` | Grant admin role |
| `npm run harakumo:env` | Push production env vars to the Harakumo project (upsert by key) |
| `npm run harakumo:deploy` | Connect `REPO_URL` and trigger a production deploy |
| `npm run build` / `start` / `typecheck` | Standard Next.js |

### Environment variables

See [.env.example](.env.example). Key ones:

- `HARAKUMO_API_KEY`, `HARAKUMO_PROJECT_ID`, `HARAKUMO_DATABASE_ID`, `HARAKUMO_BUCKET_ID`, `HARAKUMO_PAYMENTS_ACCOUNT_ID`, `HARAKUMO_AUTH_POOL_ID` — filled by setup.
- `AUTH_SECRET` — HS256 secret for the session cookie (generated by setup).
- `APP_URL` — public URL (used in emails, Stripe success/cancel URLs).
- `ADMIN_EMAILS` — comma list; these accounts become admins.
- `MAIL_MODE` — `harakumo` (real email) or `dev` (console + `/dev/mailbox`).
- `COD_ENABLED`, `FREE_SHIPPING_OVER_CENTS`, `SHIPPING_FLAT_CENTS`, `TAX_RATE`, `CURRENCY`.
- `PAYMENTS_TRUST_SUCCESS_REDIRECT` — if the provider's session list can't confirm a payment, trust the Stripe success redirect (default `false`).
- `PAYMENTS_WEBHOOK_SECRET` — shared secret for `POST /api/webhooks/payments` (`x-webhook-secret` header).

## Architecture

```
src/
  lib/
    harakumo.ts        typed REST client (projects, databases, storage, payments, auth, mail, ai, env, deployments)
    db/                Db interface → RemoteD1Db (Harakumo) | LocalSqliteDb (dev fallback); schema.ts; migrate.ts
    auth/              scrypt passwords, JWT cookie + DB sessions, OTP issue/verify, in-memory rate limiter
    mail/              sendMail() (Harakumo Mail or dev mailbox) + HTML templates
    repo/              users, products, addresses, coupons, orders
    checkout.ts        priceCart → coupon → totals → reserve stock → create order → payment session → emails
    payments.ts        createCheckoutSession / verifyCheckoutSession (Harakumo Payments)
    storage.ts         presigned upload + media proxy helpers (Harakumo Storage)
    ai.ts              recipe/tips via Harakumo AI gateway
  app/
    (storefront) /, /shop, /shop/[slug], /cart, /checkout, /checkout/success|cancel
    (auth) /signup, /login, /verify-email, /forgot-password, /reset-password
    /account, /account/orders[/id], /account/addresses, /account/security
    /admin, /admin/products[/new|/id], /admin/orders[/id], /admin/users
    /api/** (see below), /dev/mailbox
scripts/               harakumo-setup, migrate, seed, query, promote-admin, harakumo-env, harakumo-deploy, generate-images
```

### API

| Method & path | Auth | Purpose |
|---|---|---|
| `POST /api/auth/signup` | – | Create account, send verification code |
| `POST /api/auth/verify-email` | – | Verify code → session |
| `POST /api/auth/login` | – | Password sign-in (re-sends code if unverified) |
| `POST /api/auth/otp/request` | – | Send code for `verify_email` / `login` / `reset_password` |
| `POST /api/auth/otp/login` | – | Passwordless sign-in with code |
| `POST /api/auth/password/reset` | – | Reset password with code (signs out everywhere) |
| `POST /api/auth/logout`, `GET /api/auth/me` | cookie | Session |
| `GET/PUT /api/account/profile`, `POST /api/account/password` | user | Profile / password |
| `GET/DELETE /api/account/sessions` | user | List / revoke sessions (`?sid=` or `?all=1`) |
| `GET/POST /api/account/addresses`, `PUT/DELETE /api/account/addresses/:id` | user | Address book |
| `GET /api/products`, `GET /api/products/:slug`, `GET /api/categories` | – | Catalogue (q, category, sort, inStock, ids, limit, offset) |
| `GET/POST /api/products/:slug/reviews`, `DELETE /api/reviews/:id` | –/verified user | Ratings & reviews |
| `POST /api/cart/price`, `POST /api/coupons/check` | – | Server-side pricing / coupon validation |
| `POST /api/checkout` | verified user | Place order → `redirectUrl` for card |
| `POST /api/checkout/confirm` | user | Confirm card payment after redirect |
| `GET /api/orders`, `GET /api/orders/:id`, `POST /api/orders/:id/cancel` | user | Orders |
| `GET /api/payments/status` | – | Which payment methods are live |
| `POST /api/webhooks/payments` | secret | Mark orders paid/failed from provider events |
| `GET /api/media/*` | – | Streams private storage objects (product photos) |
| `POST /api/ai/recipes` | – | AI tips for a product |
| `GET /api/admin/stats`, `GET/POST /api/admin/products`, `GET/PUT/DELETE /api/admin/products/:id`, `GET /api/admin/orders`, `GET/PATCH /api/admin/orders/:id`, `GET /api/admin/users`, `PATCH /api/admin/users/:id`, `POST /api/admin/upload`, `GET/POST /api/admin/categories`, `GET/POST /api/admin/coupons`, `PATCH/DELETE /api/admin/coupons/:id`, `GET/POST /api/admin/payments` | admin | Admin |
| `GET /api/health` | – | DB latency + integration status |

All mutations validate input with zod and return `{ error }` JSON on failure.

## Run Fruitly on Harakumo

Fruitly is open source (MIT) and is published on [Nucleus](https://nucleus.harakumo.com/-/explore),
Harakumo's code home. Download it there (Code → Download ZIP), then:

1. **Create an API key** at [harakumo.com/dashboard](https://harakumo.com/dashboard) → Settings → API keys,
   and put it in `.env.local` as `HARAKUMO_API_KEY` (copy `.env.example` first). Set `ADMIN_EMAILS`
   to your own address and `AUTH_SECRET` to a long random string (`openssl rand -hex 32`).
2. **Set up the backend** with `npm run harakumo:setup`. It creates the project, the database, the
   storage bucket and the auth pool, turns on payments, runs the migrations, seeds the catalogue and
   writes the ids back to `.env.local`.
3. **Send the production environment** to the project with
   `APP_URL=https://<your-project>.harakumo.app npm run harakumo:env`.
   `.env.local` itself is never uploaded.
4. **Deploy** with `npm run harakumo:deploy`. It builds locally, uploads the source with the
   prebuilt output, waits for the build and prints the live URL. Or deploy the folder with the CLI
   (`npm i -g @harakumo/cli`, `harakumo login --key <your key>`, `harakumo deploy <project id> .`),
   or ask your AI assistant with the Harakumo connector.

Fruitly is a Node server (Next.js), so it runs as a **server app** (Pro plan and up). Every deploy is
saved as a commit in the project's private Nucleus repo. Card payments switch on by themselves once
your payments account finishes onboarding; until then checkout offers cash on delivery.

## Security notes

- **Authentication** is the app's own: scrypt password hashes, database sessions, emailed one-time
  codes, password reset by code and per-device session revoke. Users are also mirrored into a
  Harakumo auth pool as a directory.
- **Payments**: card checkout appears once the connected account can take charges (the app checks
  `GET /api/projects/:id/payments`, cached 60 s, with a *Refresh* button in Admin → Dashboard). Orders are
  confirmed on return from checkout, through the webhook at `/api/webhooks/payments`
  (`PAYMENTS_WEBHOOK_SECRET`), or by an admin marking them paid. Leave
  `PAYMENTS_TRUST_SUCCESS_REDIRECT=false` in production.
- **Product images** are private objects in Harakumo Storage, served through `/api/media/*` with
  caching headers.
- **Mutating API routes** refuse cross-origin browser requests (an Origin check) on top of
  `SameSite=Lax` cookies. Rate limits are per instance, in memory; one-time code attempts are also
  capped in the database.
- `/dev/mailbox` shows every email the app sent, codes included. It is off in production; keep
  `MAIL_DEV_MAILBOX=false` anywhere real people sign in.
